# Requirements: Ketu v1.3 — Chiron & Engine Hardening

**Defined:** 2026-05-29
**Core Value:** Cycle calculations must be correct, tested, and performant.

## v1.3 Requirements

Requirements for the v1.3 milestone. Each maps to exactly one roadmap phase. Ordered by axis: Quality → Ephemeris refactor → Spike Chiron → Chiron → Docs → Release.

### Quality

- [ ] **QAL-10**: Project test coverage reaches 100% (close `ketu/houses/_ecliptic.py` ~64% — lines 43-47 + 69-73, RA↔λ conversions load-bearing for Placidus/Koch — and all other remaining gaps)
- [ ] **QAL-11**: Division-by-zero at `orbital.py:755` (`np.arcsin(z / r)`) is guarded (`r` floored, e.g. `np.maximum(r, 1e-10)`); a regression test pins the degenerate `r→0` case
- [ ] **QAL-12**: Public-API docstrings gain example/Notes depth (interrogate + numpydoc already pass quantitatively; this lifts qualitative depth — runnable examples and accuracy/edge-case Notes)

### Ephemeris Refactor

- [ ] **REF-01**: The per-body if-elif in `planets.py:calc_planet_position` is extracted into a per-body strategy structure (a new body becomes a registered strategy, not another branch)
- [ ] **REF-02**: `orbital.py:get_body_position` is split so `orbital.py` (~856 LOC) decomposes into focused units; behavior is byte-stable (existing ephemeris regression tests unchanged)
- [ ] **REF-03**: Duplicated natal fixtures across the four subpackage conftest.py files (charts / synastry / composite / returns) are consolidated into a root `tests/conftest.py`; subpackage tests consume the shared fixtures

### Spike Chiron

- [ ] **SPK-01**: A Chebyshev-by-segment fit for Chiron is validated on real measurements — segment size (~32 d candidate), polynomial degree, coefficient array size, and achieved longitude accuracy vs Swiss Ephemeris are measured and documented
- [ ] **SPK-02**: The spike confirms achievable accuracy is < 0.01° longitude vs Swiss Ephemeris over the supported date range, OR documents the real boundary and the tuning needed to reach it (go/no-go decision for the Chiron phase recorded)

### Chiron

- [ ] **CHIR-01**: Chiron Chebyshev coefficients are generated by an offline pyswisseph generator (build-time) and shipped as a `.npz` artifact inside the package; runtime evaluation is 100% NumPy (pure-NumPy runtime contract + AGPL isolation preserved). pyswisseph is also the validation/oracle reference in tests (test-only, as in v1.1/v1.2) — it is NEVER a runtime dependency of the installed wheel
- [ ] **CHIR-02**: Chiron is wired in as the 14th body at all six mapped insertion points (`core.py` bodies array, `orbital.py` ORBITAL_ELEMENTS, `planets.py` BODY_INDICES + SWE_IDS + `calc_planet_position` strategy + `get_planet_name` + `calculate_all_positions`)
- [ ] **CHIR-03**: `calc_planet_position` returns Chiron longitude (and the position vector) within the spike-validated accuracy bound vs Swiss Ephemeris; a regression test pins reference values across multiple dates spanning Chiron's ~50.7-year period
- [ ] **CHIR-04**: The bodies axis moves 13→14: the `test_body_count_frozen_at_thirteen` ratchet (`tests/test_ketu.py:110`) and the synastry/transits/charts body-count assertions are updated to 14; the change is documented as a breaking positional-contract change for Kala (Kala adapts to Ketu)
- [ ] **CHIR-05**: Chiron participates in the existing chart/aspect/cycle machinery (appears in `compute_chart`, aspect detection, and `calculate_all_positions`) with no special-casing beyond the per-body strategy

### Documentation

- [ ] **DOC-10**: The 12 frozen `docs/source/` pages (stuck at v1.0, 2026-02-12) are brought up to the full current surface — every v1.1/v1.2/v1.3 feature is documented (configurable aspects, six house systems, `compute_chart`/`CHART_DTYPE`, synastry, midpoint composite, solar + lunar returns, Arabic Parts, Chiron)
- [ ] **DOC-11**: New Sphinx pages exist for the major new feature areas (relational charts, predictive charts/returns, Arabic Parts, Chiron) with runnable examples
- [ ] **DOC-12**: The French translation is regenerated via the existing gettext infra (`docs/locale/`, `docs/Makefile`, `docs/migrate_translations.py`) — no manual duplication; `docs/` builds clean en + fr

- [ ] **DOC-13**: All 17 `docs/locale/fr/LC_MESSAGES/*.po` catalogs have 100% translated `msgstr` (zero empty/English-fallback entries) covering every page; translation is regenerated and compiled through the existing gettext infra (`docs/Makefile`); `.mo` catalogs committed; Sphinx builds clean for BOTH en and fr (no new warnings vs the Phase 25/26 baseline of 1 warning each — `display_version` theme warning only).

### Release

- [ ] **REL-10**: Version bumped to 1.3.0; CHANGELOG `[1.3.0]` entry (additive features + the Chiron breaking-contract note for Kala); UPGRADING.md notes the 13→14 positional change

## Out of Scope

Explicitly excluded for v1.3. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| `pyswisseph` as runtime dependency | Validation/oracle (tests) and offline coeff generation (build) ARE allowed, as in v1.1/v1.2; only a *runtime* dep of the installed wheel is excluded (AGPL + pure-NumPy brand promise) — Chiron runtime uses embedded coeffs |
| scipy / other runtime deps | Pure-NumPy contract non-negotiable; Chebyshev eval is bespoke NumPy |
| Any body beyond Chiron (centaurs, asteroids, fixed stars) | Pure-NumPy contract holds; no additional bodies planned — Chiron is the single deliberate addition this milestone |
| Davison composite | Engine + Chiron focus this milestone; midpoint composite already shipped in v1.2 |
| 5 remaining Hermetic Lots | Competing tradition variants; v1.2 registry absorbs them additively later |
| Progressions / directions | Predictive techniques distinct from transits (already shipped, v0.4.0) and from return charts |
| Exposing Chiron as a separate additive index | Decided to break the 13→14 freeze cleanly; Kala adapts (Ketu is source of truth) |
| Timezone handling inside Ketu | UTC remains required; conversion is the caller's responsibility |
