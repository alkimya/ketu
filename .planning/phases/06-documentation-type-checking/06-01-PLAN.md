    **Structure the entry as follows (100-150 lines):**

    ```
    ## [1.0.0] - 2026-02-XX

    ### BREAKING CHANGES

    **This is a MAJOR version bump. See UPGRADING.md for detailed migration guide.**

    #### Removed: Export modules (chart and icalendar)

    - Removed modules: `ketu.export.chart`, `ketu.export.icalendar`
    - Removed functions:
      - `draw_zodiacal_chart()` — Chart rendering
      - `export_lunations_to_ical()` — iCalendar lunation export
      - `export_aspects_to_ical()` — iCalendar aspect export
      - `export_transits_to_ical()` — iCalendar transit export
    - Removed constants: `PLANETS_DEFAULT`, `BIG_FIVE` (from export module)
    - Why: Ketu 1.0 is a pure calculation library. Visualization belongs in application layers.
    - Migration: See UPGRADING.md, or pin to `ketu==0.4.0`

    #### Removed: Optional dependencies

    - Removed: matplotlib, icalendar, svgwrite as optional dependencies
    - Removed install extras: `ketu[chart]`, `ketu[icalendar]`, `ketu[all]`
    - Core is now NumPy-only: `pip install ketu`

    #### Removed: Pandas dependency

    - `generate_aspect_timeline()` returns NumPy structured array (was DataFrame)
    - `AspectTimeline.to_pandas()` removed
    - Migration: `import pandas as pd; df = pd.DataFrame(timeline)` for manual conversion

    #### Renamed: Velocity functions (breaking)

    - `vlong()` → `long_velocity()`
    - `vlat()` → `lat_velocity()`
    - `vdist_au()` → `dist_velocity_au()`
    - Why: Explicit names prevent confusion (was "v" prefix ambiguous)

    #### Changed: Public API surface

    - `ketu.__init__.py` exports only metadata + core constants
    - Functions accessed via submodule imports: `from ketu.calculations import long`
    - `ketu.__all__` explicitly lists public API

    ### Fixed (Correctness)

    **IMPORTANT: These fixes change calculation results. Recompute cached 0.4.0 results.**

    - Cache operator precedence bug: `use_cache=False` was ignored due to missing parentheses
    - Aspect vectorization non-determinism: `calculate_aspects_vectorized()` now returns consistent results
    - Moon velocity wrapping: Correct velocity at 360°/0° boundary (was showing ±360° spikes)

    ### Added

    - Numerical precision guarantees documented (±1e-6° for angular separation)
    - Type hints for all public functions (mypy strict mode)
    - NumPy-style docstrings with Examples section
    - Vectorized ResonanceField._get_trace() (10-100x faster)
    - Standardized error messages with context (ValueError includes received value + valid options)

    ### Changed

    - Complex number representation used internally for cycle calculations
    - Two-layer caching strategy documented (LRU for single-point, EphemerisCache for batch)
    - Test coverage: 91.48% overall (cache 89%, cycles 96%)
    - 250 tests pass across all modules

    ### Performance

    - Vectorized batch ephemeris calculations (calc_planet_position_batch)
    - ResonanceField._get_trace() uses batch calculations (eliminates Python loop)
    ```
