<objective>
Build the dynamic harmonic generator: a brand-new, table-independent function
`generate_harmonic_aspects(h)` that emits `(name, angle, coef, harmonic, symbol)`
specs for ANY integer harmonic `h` using the locked unified 360° convention. This
is the foundation the entire phase depends on — every downstream consumer
(`calculate_aspects`, synastry, cycles, find_aspects_between_dates) iterates the
rows this function produces.

Purpose: Lets a user generate first-class aspects for arbitrary harmonics (7, 11,
17…) on the fly, with a drop-in dtype identical to `core.aspects`, WITHOUT touching
the frozen 14-row table or its sha256 fingerprints, and WITHOUT ever consulting
`_VALID_HARMONICS` (which would reject H7).

Output: `ketu/aspects/harmonics.py` (new module), public exports in
`ketu/aspects/__init__.py`, and a new test file `tests/test_dynamic_harmonics.py`
that holds the 100% coverage gate for every new line.

Covers requirements: ASP-04 (public generator for any integer h), ASP-05 (360°
convention), ASP-08 (frozen table + `_VALID_HARMONICS` never gated).
</objective>

Define, in order:

1. `HARMONIC_DTYPE = np.dtype([("name","S16"),("angle","f4"),("coef","f4"),("harmonic","i4"),("symbol","U4")])`
   — this MUST exactly match `ketu/core.py:113`. This dtype is the drop-in contract:
   anything that consumes `core.aspects` can consume the generator's output.

2. `DynamicAspectSpec = Optional[Union[np.ndarray, List[np.ndarray]]]`
   — the public type alias for the `dynamic_specs=` parameter threaded through all
   consumers in plans 02/03. Accepts a single structured array OR a list of them
   (consumers concatenate). Add `from typing import List, Optional, Union`.

3. `_fold_to_0_180(angle_deg: float) -> float` — implements the locked convention
   `min(a % 360, 360 - a % 360)`. Implement as:
   `a = angle_deg % 360.0; return a if a <= 180.0 else 360.0 - a`.
   Full numpydoc docstring (Parameters/Returns) — numpydoc gate is BLOCKING.

4. `generate_harmonic_aspects(h: int) -> np.ndarray`:
   - Validate `h`: must be a real int (reject bool explicitly — `bool` is a subclass
     of `int`; mirror the presets.py pattern at lines 165-168). Require `2 <= h <= 64`
     (Claude's Discretion bounds per RESEARCH Open Question 1 — h=1 is degenerate/empty,
     >64 is impractical). Raise `ValueError` with a clear message naming the bound on
     out-of-range / wrong-type input. NEVER an IndexError, NEVER a silent empty array.
   - Build rows for `k` in `range(1, h // 2 + 1)`:
       `angle = _fold_to_0_180(k * 360.0 / h)`,
       `coef  = k / h`,
       `name  = f"H{h}-{k}".encode()`  (S16 stores bytes),
       `harmonic = h`,
       `symbol = ""`  (blank U4 for ALL dynamic rows — same convention as Decile/Novile).
   - Return `np.array(rows, dtype=HARMONIC_DTYPE)`.
   - This guarantees: 0°/360° never emitted (k starts at 1, stops before k=h), mirror
     pairs deduplicated (only k=1..h//2 since `fold(k·360/h)==fold((h-k)·360/h)`),
     deterministic ordering by k.
   - Full numpydoc docstring with an Examples block (doctest). Use `round()` in the
     doctest to dodge f4 repr fragility (Pitfall 5) — e.g.:
       `>>> specs = generate_harmonic_aspects(7)`
       `>>> len(specs)` -> `3`
       `>>> specs['name'].tolist()` -> `[b'H7-1', b'H7-2', b'H7-3']`
       `>>> [round(float(a), 2) for a in specs['angle']]` -> `[51.43, 102.86, 154.29]`
       `>>> [round(float(c), 4) for c in specs['coef']]` -> `[0.1429, 0.2857, 0.4286]`
       `>>> specs['symbol'].tolist()` -> `['', '', '']`
     Verify these exact rounded values before committing (run the doctest).

5. `__all__ = ["generate_harmonic_aspects", "HARMONIC_DTYPE", "DynamicAspectSpec", "_fold_to_0_180"]`.

Type hints everywhere; UTC/NumPy-first conventions per CLAUDE.md.
