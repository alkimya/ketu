24-RESEARCH Gap 4 and 23-DECISION §5. Components:

1. `_load_chiron_data() -> dict[str, np.ndarray]` decorated with `@lru_cache(maxsize=1)`:
   load via `importlib.resources.files("ketu.data").joinpath("chiron_coeffs.npz").open("rb")`,
   then `npz = np.load(fh)` and return `{k: npz[k] for k in npz.files}`.
   CRITICAL: do NOT use `__file__` string paths or `pkg_resources` (AGPL/zipimport anti-patterns).

2. `_eval_chiron_qty(jd, coeffs, seg_starts, seg_len) -> float`:
   `si = int((jd - seg_starts[0]) / seg_len)`; clamp `si = max(0, min(si, len(seg_starts)-1))`;
   `t = float(np.clip(2.0*(jd - seg_starts[si])/seg_len - 1.0, -1.0, 1.0))`;
   return `float(np.polynomial.chebyshev.chebval(t, coeffs[si]))`. The clamp on si AND the clip
   on t are the out-of-range JD guards (must be reachable by tests, see plan testing below).

3. `_chiron_scalar(jd) -> tuple[float, ...]` (6 values): evaluate lon (`% 360.0`), lat, dist at
   jd; evaluate again at jd+0.01 (jd_delta=0.01, matching _make_planet_scalar); compute speeds by
   finite difference; wrap-correct dlon ( >180 → -=360, <-180 → +=360 ); return
   (lon, lat, dist, dlon/jd_delta, (lat1-lat)/jd_delta, (dist1-dist)/jd_delta).

4. `_chiron_vec(jd_array) -> tuple[np.ndarray, ...]` (6 arrays): loop over jd_array calling
   `_chiron_scalar`, stack into (n,6). THEN apply aberration internally to lon/lat to match the
   `_make_planet_vec` pattern (planets.py ~L269-273: `aberration_correction(lon, lat, jd)` per
   element, add dlon/dlat). Import `aberration_correction` from `.coordinates`. This keeps the
   batch path consistent with the scalar router which applies aberration for planet_id>=2.
   Return the 6 columns as separate arrays.

5. Type hints everywhere; numpydoc-style docstrings on every public/strategy fn (interrogate>=95%
   gate). Module docstring noting pure-NumPy, no pyswisseph. French is fine per persona.

Do NOT touch planets.py, core.py, or any registry in this plan — registration is plan 24-03.
