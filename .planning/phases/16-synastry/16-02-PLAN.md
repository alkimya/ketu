<objective>
Implement `calculate_synastry(chart_a, chart_b, aspects="classical", orbs="synastry", mode="filtered")` — the cross-chart aspect compute engine. Consumes two `CHART_DTYPE` scalar records (Phase 14), enumerates the full Cartesian product of 15×15 = 225 body pairs (13 canonical bodies + ASC + MC on each side, self-pairs INCLUDED per locked decision), applies first-aspect-wins matching against the synastry-tightened orb table, computes the velocity-based `applying` field from natal speeds, and returns a `SYNASTRY_DTYPE` structured array in either dense (225 rows with `-1`/`NaN` sentinels) or filtered (only aspected rows) mode.

Purpose: Deliver SYN-01, SYN-02, SYN-03, SYN-04 in a single composition layer that reuses every existing v1.2 primitive (CHART_DTYPE, resolve_aspect_set, distance, _BODY_ORBS_15) and adds zero astronomical state. The filtered-vs-dense duality, the velocity-based `applying` semantics, and the cross-product-not-triu_indices loop are the three novelties this plan ships.

Output: `ketu/synastry/api.py` + updated `__init__.py` + 3 test files (unit + applying + idempotency property). Public surface: `from ketu.synastry import calculate_synastry` resolves and computes correctly on a Phase 14 `CHART_DTYPE` pair.
</objective>

3. **Public function** `calculate_synastry(chart_a, chart_b, aspects="classical", orbs="synastry", mode="filtered") -> np.ndarray`:
   - Type hints exactly as 16-RESEARCH.md §Example 3 line 574-580.
   - Algorithm: follow 16-RESEARCH.md §Example 3 lines 616-681 verbatim, with these mandatory invariants:
     - Resolve aspect mask via `resolve_aspect_set(aspects)` (length-14 bool mask).
     - Resolve orb factor via `resolve_orb_set(orbs)` (float scalar).
     - Extend both charts via `_extend_body_data` → 15-body lons + speeds.
     - Cross-product enumeration via `np.indices((15, 15))` then `.ravel()` → flat shape `(225,)` for `i_flat`, `j_flat`. **CRITICAL**: do NOT use `triu_indices` — this is the locked Pitfall 1 from 16-RESEARCH.md (self-pairs and ordering both matter).
     - Initialize `out = np.empty(225, dtype=SYNASTRY_DTYPE)` with sentinel defaults (`aspect_type=-1`, `orb=np.nan`, `applying=False`, `orb_limit=np.nan`). `body_a/body_b/lon_a/lon_b` always populated (even for non-aspected pairs in dense mode).
     - Loop over `selected_indices = np.where(mask)[0]` (canonical aspect indices). For each aspect:
       - Compute per-pair `orbs_pair = (_BODY_ORBS_15[i_flat] + _BODY_ORBS_15[j_flat]) / 2.0 * coef * factor` (shape (225,)).
       - Conjunction (i_asp == 0): `in_orb = (dist <= orbs_pair) & (~matched)`; `delta = -dist`.
       - Other aspects: `in_orb = (np.abs(dist - ang) <= orbs_pair) & (~matched)`; `delta = ang - dist` (signed orb, Phase 14 D-05 convention; positive when distance < aspect_angle).
       - Compute `applying = (np.sign(delta) * (speed_a - speed_b)) > 0` (Pitfall 4: signed convention, do NOT call `np.abs` on speeds).
       - Write to `out[in_orb]` for the four mutable fields and update `matched |= in_orb` (first-aspect-wins, mirrors `ketu/aspects/calculator.py:204` convention).
     - Mode dispatch:
       - `mode == "dense"` → return `out` (shape (225,), full table).
       - `mode == "filtered"` → return `out[out["aspect_type"] >= 0]` (canonical body-pair order preserved; Pattern 5 from 16-RESEARCH.md).
       - Other → `ValueError(f"unknown mode {mode!r}; expected 'dense' or 'filtered'")`.
