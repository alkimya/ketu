  The docstring should explain:
  1. **Two caching layers** exist by design:
     - `@lru_cache` on `calc_planet_position()` in `ephemeris/planets.py`: In-memory memoization for repeated single-point lookups. Thread-safe, auto-managed, ~0.01ms hit latency.
     - `EphemerisCache` in `cache/ephemeris_cache.py`: Disk-backed monthly pre-computation for batch operations. Cross-session persistence, vectorized batch API, ~10x faster for large arrays.
  2. **When to use each:**
     - LRU cache: Automatic — decorates `calc_planet_position()`, no user action needed for single-point calls.
     - EphemerisCache: Explicit — user creates instance and calls `ensure_range()` for batch workflows.
  3. **Not redundant:** They optimize different access patterns (single-point vs batch, in-memory vs persistent).
