# Phase 02.1 Plan 02: Rename Velocity Functions to Explicit Names

**Renamed vlong/vlat/vdist_au → long_velocity/lat_velocity/dist_velocity_au across entire codebase, removing ambiguous "v" prefix for clarity before 1.0.0 release**

## Objective

Rename the ambiguous velocity functions `vlong()`, `vlat()`, and `vdist_au()` to explicit, self-documenting names: `long_velocity()`, `lat_velocity()`, and `dist_velocity_au()`. The "v" prefix was causing real confusion in downstream Kala/Solaris integration where Claude interpreted `vlong` as "longitude value" instead of "longitude velocity." Since we're heading to 1.0.0, we remove the old names entirely (no deprecation) and provide comprehensive migration documentation.

## Technical Details

### Naming Convention Chosen

**Pattern:** `{coordinate}_velocity()`

- `long_velocity()` - longitude velocity (not `velocity_long()` or `long_vel()`)
- `lat_velocity()` - latitude velocity
- `dist_velocity_au()` - distance velocity (AU retained for unit clarity)

**Rationale:**
1. Coordinate name first (matches position functions: `long()`, `lat()`, `dist_au()`)
2. Full `_velocity` suffix (no abbreviation ambiguity)
3. Reads naturally: "longitude velocity", "latitude velocity"

### Why No Deprecation Period?

This is a breaking release (0.4.x → 1.0.0) with comprehensive migration documentation. The ambiguity of the "v" prefix was causing real bugs in production (Kala/Solaris integration). A clean break with clear migration guide is more valuable than a deprecation cycle.
