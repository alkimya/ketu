## Objective

Fix Moon velocity wrapping bug at the 360/0 degree boundary in both scalar and vectorized code paths. When the Moon's longitude crosses from ~359 to ~0 degrees, the finite difference velocity calculation was producing wildly wrong values (-36000 deg/day instead of +14 deg/day). This occurred once per lunar sidereal month (~27 days) and silently corrupted downstream cycle calculations in Solaris/Kala.

```python
# Handle longitude wrapping at 360/0 boundary
```

**Vectorized fix** (line 470, inside `calc_planet_position_batch()` Moon block):

```python
# Handle longitude wrapping at 360/0 boundary (vectorized)
lon_diff = lon2 - lon

lon_diff = np.where(lon_diff < -180, lon_diff + 360, lon_diff)
lon_speed = lon_diff / jd_delta
```

## Technical Details

### Root Cause

The finite difference velocity calculation used a simple subtraction `lon2 - lon` without handling angular wrapping. When the Moon's longitude crossed from ~359.87° to ~0.13° in a 0.01-day interval:

- `lon = 359.87`
- `lon2 = 0.13`
- `lon_diff = 0.13 - 359.87 = -359.74°` (wrong!)
- `lon_speed = -359.74 / 0.01 = -35974 deg/day` (wildly wrong!)

The correct calculation wraps the difference:
- `lon_diff = -359.74` → `lon_diff + 360 = 0.26°` (correct!)
- `lon_speed = 0.26 / 0.01 = 26 deg/day` (reasonable, varies from 11-15 deg/day)

### Why Moon Only?

The Sun moves ~1 deg/day and can never wrap in a 0.01-day delta. The Moon moves ~11-15 deg/day and crosses the 360/0 boundary approximately once per sidereal month (~27.3 days). Other planets are even slower than the Sun.

### Implementation Choice

The scalar path uses standard `if-elif` branching for clarity. The vectorized path uses `np.where()` for performance, applying the wrapping conditionally across arrays.
