## Marker-Preservation DO/DON'T (CRITICAL — breaks the build if violated)

DON'T:
- NEVER add `#`, `##`, `###` heading markers to a msgstr when the msgid has none. This is
  the exact Phase 25-03 `myst.header` bug. If `msgid "Examples"` then `msgstr "Exemples"` —
  NOT `msgstr "## Exemples"`.
- NEVER translate `{ref}`...``, `{doc}`...``, or any `{role}`...`` MyST role — copy verbatim.
- NEVER translate a msgid that is ENTIRELY a code span (starts+ends with backtick), e.g.
  `` `ketu.parts` `` or `` `body_id=13` `` — copy it verbatim as the msgstr.
- NEVER drop `` `` `` backticks, `**bold**`, URLs, or shape notation like `(14, 14)`.

DO:
- Translate prose headings: `msgid "House Systems"` → `msgstr "Systèmes de maisons"`.
- Keep `**bold**` markers, translate the text inside: `**Parameters:**` → `**Paramètres :**`.
- Keep backtick code verbatim, translate the description around it.
- FR colon spacing: a space before `:` `;` `!` `?` → `Paramètres :` not `Paramètres:`.
- Multiline entries: a single-line msgstr is valid for short translations; use the same
  quoted-string concatenation as the msgid for long ones.

Skip `#~`-prefixed obsolete entries. Only fill empty `msgstr ""` entries.
