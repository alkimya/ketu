### Task 1 — Implémenter `_build_aspect_matrix` dans `ketu/charts/api.py`

Ajoute le helper privé au-dessus de `compute_chart` (après `_vectorised_body_properties`) :

```python
from ketu.aspects.calculator import calculate_aspects_vectorized


def _build_aspect_matrix(
    jd_b: np.ndarray,
    aspects: AspectSetSpec,
) -> tuple[np.ndarray, np.ndarray]:
    """Build dense (13, 13) aspect matrix + orbs over leading shape S.

    Loops over S in Python (per D-16 ; acceptable for v1.2 since charts
    are typically batched at ~100s, not 100k+). Each S-element call to
    ``calculate_aspects_vectorized`` is itself vectorised over the 78
    body-pair upper-triangle. Diagonal stays at sentinel (a body has no
    aspect with itself).

    Parameters
    ----------
    jd_b : np.ndarray
        Broadcast Julian Date array, leading shape S (any compatible shape).
    aspects : AspectSetSpec
        Pass-through to ``calculate_aspects_vectorized``. ``None`` resolves
        to the CLASSICAL preset (5 majors, per D-07).

    Returns
    -------
    aspect_matrix : np.ndarray
        Shape ``S + (13, 13)``, dtype i1, canonical i_asp ∈ [0, 13] or
        ``-1`` for "no aspect". Symmetric (D-17): matrix[i,j] == matrix[j,i].
        Diagonal == ``-1``.
    aspect_orbs : np.ndarray
        Shape ``S + (13, 13)``, dtype f4, orb in degrees or ``NaN`` for
        "no orb". Symmetric. Diagonal == ``NaN``.

    Notes
    -----
    The Python loop over S is an explicit v1.2 trade-off (D-16). Profiling
    in Phase 16 (synastry) will revisit this for v1.3 if it becomes a
    bottleneck. Each S-element call has constant cost in S.
    """
    matrix = np.full(jd_b.shape + (_BODY_COUNT, _BODY_COUNT), -1,    dtype=np.int8)
    orbs   = np.full(jd_b.shape + (_BODY_COUNT, _BODY_COUNT), np.nan, dtype=np.float32)

    # np.ndindex(()) yields exactly one tuple () for a 0-d shape — the
    # scalar-jd case traverses this loop with idx==() naturally.
    # Pinned by test (cf. Assumption A1 in RESEARCH).
    for idx in np.ndindex(jd_b.shape):
        jd_scalar = float(jd_b[idx])
        records = calculate_aspects_vectorized(jd_scalar, aspects=aspects)
        # records: structured array with fields (body1, body2, i_asp, orb)
        # body1 < body2 by upper-triangle convention (calculator.py:187).
        for rec in records:
            i = int(rec["body1"])
            j = int(rec["body2"])
            i_asp = int(rec["i_asp"])
            orb = float(rec["orb"])
            # D-17: mirror upper-triangle into lower-triangle for
            # symmetric lookup convenience.
            matrix[idx + (i, j)] = i_asp
            matrix[idx + (j, i)] = i_asp
            orbs[  idx + (i, j)] = orb
            orbs[  idx + (j, i)] = orb

    return matrix, orbs
```

**Note sur la dette `resolve_aspect_set` re-call (RESEARCH §Pitfall 3)** : `calculate_aspects_vectorized` re-resolve l'`AspectSetSpec` à chaque appel (ligne 174 de l'analogue). Pour v1.2, c'est acceptable — la résolution est ~µs et la boucle S est en centaines d'itérations max (D-16 horizon de scale). Documenter dans le code via un commentaire `# TODO(v1.3): hoist resolve_aspect_set() above this loop if profiling shows hot-path cost — see RESEARCH §Pitfall 3`. NE PAS optimiser maintenant ; la dette est consciente et tracée.
