```yaml
    # Phase 20 (OPS-02 finalization): remove `continue-on-error: true` and
    # the `"GL01"` suppression in `[tool.numpydoc_validation].checks` to

    - name: Doc style audit (numpydoc — warning only, blocking from v1.2.0)
      if: matrix.python-version == '3.13'
      continue-on-error: true
      run: |
        FILES=$(find ketu -name "*.py" \

            ! -name "_*.py")
        echo "Validating $(echo "$FILES" | wc -l) files..."
        python -m numpydoc lint $FILES
```

Why this exact shape (per PATTERNS.md + RESEARCH):
- `if: matrix.python-version == '3.13'` matches the interrogate step gating verbatim.
- `continue-on-error: true` is the warning posture locked by D-04. RESEARCH § Pitfall 4 documents the UX caveat ("step shows green checkmark even when warnings present") — the leading YAML comment + the Phase 20 forward-note exist precisely to ensure this flag is found and removed at the v1.2.0 release-prep phase.
- `python -m numpydoc lint <files>` (NOT `numpydoc validate <module.attr>`) — RESEARCH § Pitfall 1 explains: `lint` is the AST-based multi-file subcommand; `validate` requires importing each object and is wrong for CI. Use `lint` always.
- File globbing via `find` excluding `lunar_calendar.py` and `_*.py` — mirrors `[tool.numpydoc_validation].exclude` regex (D-06 + D-07). Belt-and-braces: even if the config exclude misses a file, the find-filter doesn't pass it to numpydoc.
- The `echo "Validating $(echo "$FILES" | wc -l) files..."` line is the positive-signal printout requested in CONTEXT § Specifics — even on green builds the contributor sees "Validating 22 files..." in the log, not just "step succeeded".
- BLOCKING is NOT used — this is the explicit warning-only posture. Plan 02 had no `continue-on-error`; this plan does.
- Indentation: 4 spaces (matches existing steps — YAML is whitespace-sensitive).

DO NOT change Plan 02's `Doc coverage gate (interrogate ≥95%)` step or any earlier step. DO NOT add a separate install step for numpydoc — `pip install -e ".[dev]"` (line 28) already covers it because Plan 01 added numpydoc to the `dev` group.

DO NOT remove `continue-on-error: true` in this plan. Phase 20 removes it (per D-05). Removing it here would violate D-04.
