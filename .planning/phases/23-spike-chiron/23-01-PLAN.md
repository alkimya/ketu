  <action>
Create a standalone, runnable Python script (NOT a pytest test, NOT under ketu/ or
tests/). It fits Chiron's geocentric ecliptic longitude with Chebyshev-by-segment
and measures accuracy vs the Swiss Ephemeris oracle. Sophie Chen persona: module
docstring and any printed headers in French with tutoiement; comments may be French.

Hard methodology rules (from 23-RESEARCH.md Q1-Q6 — encode each, they are verified):

1. ORACLE setup. Import swisseph as swe. Resolve the ephemeris dir from, in order:
   env var SE_EPHE_PATH if set, else the known path
   '/home/loc/workspace/rahu/kerykeion/kerykeion/sweph'. Call swe.set_ephe_path(dir)
   BEFORE any swe.calc_ut. If swe.calc_ut(jd, swe.CHIRON, swe.FLG_SWIEPH|swe.FLG_SPEED)
   raises swisseph.Error, print a clear French message naming seas_18.se1 + the dir
   tried and sys.exit(1). swe.CHIRON == 15.
   Oracle call returns (xx, retflag, errmsg); xx is a 6-tuple
   (lon, lat, dist, lon_speed, lat_speed, dist_speed). Print the retflag once so the
   actual ephemeris path used (e.g. 258 SWIEPH+SPEED vs 260 MOSEPH+SPEED) is recorded.

2. DATE RANGE. Cover 1950-01-01 .. 2050-01-01 UTC. Compute jd0/jd1 via
   swe.julday(year, month, day, hour) (Gregorian, UT). total_days = jd1 - jd0
   (~36889). This guarantees the perihelion worst-case (~1996, ~2046/2047) is inside.

3. UNWRAPPED-LONGITUDE sampler. Write sample_chiron_unwrapped(jd_array) -> np.ndarray
   that, for an ascending jd_array, queries swe.calc_ut per jd, takes lon=xx[0], and
   UNWRAPS by tracking a cumulative 360 offset (diff>180 -> offset-=360; diff<-180 ->
   offset+=360) so the returned series is smooth/monotone (no 0/360 jump). Also expose
   helpers to sample lat=xx[1] and dist=xx[2] (lat/dist need no unwrapping).

4. FIT per segment. For (seg_len, degree): n_segs = ceil(total_days/seg_len). For each
   segment si: jd_s = jd0 + si*seg_len; jd_e = min(jd_s+seg_len, jd1);
   actual_len = jd_e - jd_s. FIT NODES uniform & OVERDETERMINED:
   n_fit = degree + 8; t_fit = np.linspace(-1, 1, n_fit);
   jd_fit = jd_s + (t_fit+1)/2 * actual_len. lon_fit = sample_chiron_unwrapped(jd_fit).
   Fit via numpy.polynomial.chebyshev.Chebyshev.fit(t_fit, lon_fit, degree,
   domain=[-1,1]); keep poly.coef (degree+1 coeffs).

5. VALIDATION grid DISTINCT from fit nodes and DENSER: t_val = np.linspace(-1, 1, 200);
   jd_val = jd_s + (t_val+1)/2 * actual_len; lon_true = sample_chiron_unwrapped(jd_val);
   lon_pred = numpy.polynomial.chebyshev.chebval(t_val, poly.coef).
   seg_err = np.max(np.abs(lon_pred - lon_true)). Use MAX, never RMS. Track the global
   max across ALL segments AND the jd/date of the worst segment.

6. CONFIG SWEEP. Run at minimum these configs and record each as a table row:
   (32,10) primary; (32,8); (32,12); (16,8); (64,8). For each: n_segs,
   coeffs_per_seg=degree+1, total_coeffs=n_segs*(degree+1) [lon-only],
   npz_lon_only_KB = total_coeffs*8/1024, max_err_deg, ok = max_err_deg < 0.01.
   Also compute and print the lon+lat+dist footprint for the primary config
   (total_coeffs*3*8/1024 ~ 297 KB).

7. CHOSEN-CONFIG lat/dist accuracy. For the primary (32,10): repeat the same
   fit/validate loop fitting lat and dist (each its own Chebyshev.fit) over ALL
   segments and record max |Δlat| (deg) and max |Δdist| (AU).

8. CONFIRM the pure-NumPy evaluator is implementable: include a tiny self-check that
   for one sample t-array, numpy.polynomial.chebyshev.chebval(t, coef) matches the
   poly(t) Chebyshev object via np.allclose, and print "evaluateur chebval pur-NumPy:
   OK". (No scipy anywhere in the script.)

9. OUTPUT. Print a clean ASCII table of the config sweep (columns: seg_d, degree,
   n_segs, coeffs/seg, total_coeffs, npz_lon_KB, max_err_deg, <0.01?) plus the
   primary-config lat/dist errors, the worst-segment date, the retflag, and the
   pure-NumPy evaluator confirmation. Wrap the whole run in `if __name__ == "__main__":`.
   Performance: full sweep should finish in a few minutes; if oracle sampling is the
   bottleneck, sample each unique jd once (fit + validate grids are disjoint, so no
   dedup is required across them — just keep per-call swe usage minimal).

Do NOT register this in pytest, do NOT import it from ketu/, do NOT edit pyproject.toml.
