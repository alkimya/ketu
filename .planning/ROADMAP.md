### 🚧 v1.3 Chiron & Engine Hardening (Phases 21-26) — IN PROGRESS

**Milestone Goal:** Embed Chiron (Chebyshev-by-segment coefficients, pure-NumPy runtime) as the 14th body — after hardening the fragile ephemeris engine and lifting project quality to 100% — then bring the Sphinx docs (en+fr) up to the full v1.1/v1.2/v1.3 surface and ship `ketu==1.3.0`.

**Axis order (BINDING):** Quality → Ephemeris refactor → Spike Chiron → Chiron → Docs → Release.
Refactor lands BEFORE Chiron (clean per-body strategy, not aggravated if-elif debt). Spike lands BEFORE Chiron (measure achievable accuracy + go/no-go). Docs land BEFORE Release.

**Cross-cutting constraints (v1.3):**

- **Pure-NumPy runtime is NON-NEGOTIABLE.** Chiron coeffs are generated by an offline, pyswisseph-build-only generator and shipped as a `.npz` artifact; runtime evaluation is 100% NumPy. `pyswisseph` stays test/build-only (AGPL isolation). No scipy or any new runtime dep.
- **Vectorizable** — all new calculations batchable over `jd` arrays; no Python loops in hot paths.
- **Python 3.10+** — CI matrix unchanged (3.10–3.13); mypy `--strict` clean.
- **Coverage gates** — v1.3 lifts project coverage to 100% (QAL-10) and holds it; doc gates (`interrogate ≥95%`, `numpydoc validate`) stay BLOCKING.
- **D-08 breaking change** — the bodies axis goes 13→14 in Phase 24, deliberately breaking the `test_body_count_frozen_at_thirteen` ratchet (`tests/test_ketu.py:110`) and the internal Ketu↔Kala positional array contract. Decided: BREAK the freeze; Kala adapts to Ketu (source-of-truth library). Version stays **1.3.0** — the public Ketu API is additive; only the internal positional contract changes.
