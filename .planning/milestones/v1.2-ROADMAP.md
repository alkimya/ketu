# Milestone v1.2: Astrologie relationnelle et prédictive

**Status:** ✅ SHIPPED 2026-05-28
**Phases:** 13-20 (8 phases)
**Total Plans:** 35 (5 + 5 + 4 + 5 + 4 + 5 + 3 + 4)

## Overview

Ketu became a full relational and predictive astrology framework, strictly non-breaking (every API additive — no default change on existing APIs, no export removed; v1.1 burned the BREAKING quota). v1.2 delivered a chart-abstraction keystone that synastry, composite, and returns all build on; three new house systems proving the v1.1 registry extensibility claim; relational charts (synastry + midpoint composite); predictive charts (solar + lunar returns sharing one pure-NumPy `_solve_return` core); and an extensible Arabic Parts framework — closing with `ketu==1.2.0` on PyPI via OIDC.

## Cross-Cutting Constraints (v1.2)

- **Non-breaking minor strict** — All new APIs additive; no default change on existing APIs; no exports removed.
- **Pure-NumPy contract** — No new runtime dependencies. `pyswisseph` test-only (AGPL non-contamination); no scipy.
- **Python 3.10+** — CI matrix unchanged (3.10–3.13).
- **Vectorizable** — All new calculations batchable over `jd` arrays; no Python loops in hot paths.
- **UTC-only** — Timezone conversion is the caller's responsibility.
- **Coverage gates** — ≥90% project, ≥85% per module, ≥95% on new modules.
- **Doc gates** — From Phase 13 onward, every public function passes `numpydoc validate` and contributes to `interrogate ≥95%`.
- **Mypy `--strict`** clean across the package.

## Milestone Summary

**Decimal Phases:** None inserted in v1.2.

**Key Decisions:**

- Chart abstraction (`CHART_DTYPE` / `compute_chart` / `is_day_chart`) built as the keystone before SYN/COMP/RET (Rationale: reused unchanged by all four downstream modules).
- `is_day_chart` via ASC-delta rather than horizon altitude (Rationale: consistent with the ASC stored in the same `CHART_DTYPE`).
- Single shared `_solve_return` for solar + lunar with central wrap handling (Rationale: Phase 18 Success Criterion #3; grep ratchet forbids inline bisection in either API).
- Self-consistency oracle at 0.0001° as PRIMARY gate; pyswisseph cross-check test-only with per-body tolerance (Rationale: surfaces a genuine ephemeris-theory gap rather than masking it; runtime stays pure NumPy).
- Arabic Parts reduced from 8 to 3 (Rationale: 5 deferred Lots have competing tradition variants; registry absorbs them in v1.3 additively).
- `pyswisseph` stays test-only (Rationale: AGPL non-contamination, carried from v1.1).

**Issues Resolved:**

- v1.1 ops debt cleared: `interrogate`/`numpydoc` gates flipped to BLOCKING; Node 20 deprecation warnings eliminated (Node 24 actions).
- `circular_midpoint(359°, 1°)` pinned to `0.0` (not `180.0`).
- Lunar return mean-motion seed lift replaces the planned blunt `target_jd + n·27.32` seed (would have failed for most inputs).
- pyswisseph cross-check premise corrected: Sun aberration does NOT cancel; `_swisseph_body_lon` passes `FLG_TRUEPOS | FLG_NOABERR` to align with Ketu's convention.
- Test-extra package typo `pysweph` → `pyswisseph` fixed.

**Issues Deferred (v1.3):**

- Davison composite (time + lat/lon midpoints).
- 5 remaining Hermetic Lots (Eros, Necessity, Courage, Victory, Nemesis).
- Chiron + Centaurs, asteroids, fixed stars (require swisseph runtime or Chebyshev-fit pipeline).
- Transits / progressions / directions.
- Astro.com manual cross-check on resolved instants (anti-bot blocked; pyswisseph CI substitute is strictly stronger).

**Technical Debt Incurred:**

None of significance — all eight phases verified PASSED at their success criteria. The deferred items above are scope decisions, not shortcuts.
