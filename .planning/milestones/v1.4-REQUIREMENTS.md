# Requirements: Ketu — Milestone v1.4 Dynamic Harmonics & Chiron Range

**Defined:** 2026-06-02
**Core Value:** Cycle calculations must be correct, tested, and performant. If the math is wrong, nothing downstream matters.

**Outcome:** All 18 requirements delivered. The dynamic-harmonic capability shipped as a strictly additive parallel path; the frozen sha256-fingerprinted `core.aspects` table and its named presets stayed byte-identical. The only behaviour change (Chiron orb 0°→4°) is documented in CHANGELOG. Runtime stayed pure NumPy; `pyswisseph` remained test/build-only.

## v1.4 Requirements — all delivered

### Dynamic Harmonics

- [x] **ASP-04**: A user can generate the aspects of ANY integer harmonic `h` via a new public generator (`generate_harmonic_aspects(h)`), returning angle + coefficient specs — not limited to the preset set `{1,2,3,5,6,9,10}` — _Phase 28, validated_
- [x] **ASP-05**: The generator uses the unified 360° convention — angles `fold_to_0_180(k·360/h)` for `k=1..h//2`, coefficient `k/h` — deduplicating mirror pairs and never emitting 0°/360°; unnamed high harmonics emit a blank symbol — _Phase 28, validated_
- [x] **ASP-06**: A user can pass dynamically-generated aspects to `calculate_aspects` and have them detected with correct per-pair orbs `((orb1+orb2)/2 × dynamic_coef)` — first-class through the full detection chain (scalar, vectorized, batch) — _Phase 28, validated_
- [x] **ASP-07**: Dynamic aspects flow correctly through cycles and synastry (orb derived from `core.bodies['orb']` × dynamic coefficient); no code path assumes the 14-row table for a dynamic aspect — _Phase 28, validated_
- [x] **ASP-08**: The frozen `core.aspects` table and the named-preset sha256 fingerprints are unchanged (regression-pinned); `_VALID_HARMONICS` does NOT gate the dynamic path — _Phase 28, validated_
- [x] **ASP-09**: `find_aspect_timing` and `find_aspects_between_dates` (hardcoded table-index lookups) are guarded so dynamic angles do not raise `IndexError`; off-table aspects resolve via a synthetic name — _Phase 28, validated_

### Chiron Orb

- [x] **CHIR-06**: Chiron's natal orb is 4° (Pluto parity) — single source `core.bodies['orb']` — propagating automatically to `get_orb`, synastry `_BODY_ORBS_16`, cycles, and the CLI — _Phase 29, validated_
- [x] **CHIR-07**: The byte-stable CLI fixture (`tests/cli/fixtures/v1_1_reference_output.txt`) is regenerated for the new Chiron aspects at 4° and manually audited as correct (2 new Semi-sextile lines) — _Phase 29, validated_
- [x] **CHIR-08**: Synastry test docstrings/asserts that grouped Chiron with the zero-orb points (Rahu/Ketu/Lilith) are corrected; a new explicit test pins Chiron orb = 4° — _Phase 29, validated_

### Chiron Range

- [x] **CHIR-09**: The Chiron Chebyshev accuracy on the widened 1900–2100 range is empirically validated (spike) — max |Δλ| vs Swiss Ephemeris over the extended wings (incl. the ~1895–1896 perihelion near the lower bound) is measured BEFORE committing the `.npz`; gate < 0.01° — _Phase 30, validated (degree=10/seg=32d held, max 0.001214°, 8.2× margin — no degree bump needed)_
- [x] **CHIR-10**: `ketu/data/chiron_coeffs.npz` is regenerated over 1900–2100 via the offline `tools/gen_chiron_coeffs.py` (build-only pyswisseph); embedded `jd_start`/`jd_end` reflect the new range; partial first/last segments use `actual_len` (Phase 24 fix preserved) — _Phase 30, validated (2283 segments)_
- [x] **CHIR-11**: Regression references re-pinned to span 1900–2100 (new reference longitudes pre-1950 + post-2050); accuracy regression test holds at < 0.01°; runtime eval stays pure NumPy — _Phase 30, validated_

### Documentation

## Out of Scope (v1.4)

| Feature | Reason |
|---------|--------|
| Reconciling the half-circle (table) and full-circle (dynamic) orb conventions | User accepted the ~2× smaller dynamic full-circle orbs; the two conventions coexist as independent paths — no unification |
| Replacing or extending the frozen 14-row `core.aspects` table | Fingerprint contract must hold; the dynamic path is parallel, never grows the table |
| `pyswisseph` as a runtime dependency | NumPy-only runtime + AGPL isolation non-negotiable; build-only for `.npz` regeneration |
| scipy / sympy / symbolic math for harmonics | Harmonic generation is plain NumPy arithmetic on angles; no new runtime dep |
| Any body beyond Chiron (centaurs, asteroids, fixed stars) | No new bodies in v1.4; bodies axis stays 14 → no Kala positional break |
| CLI `--harmonics h7` arbitrary-harmonic flag | Deferred (ASP-F1) — return-type + byte-stability work; Python API is the v1.4 surface |
| Chiron range beyond 1900–2100 | 1900–2100 covers all relevant birth/event dates + near-future projection; wider range adds segments/size for no demand |
| Davison composite, remaining Hermetic Lots, progressions/directions | Still deferred from v1.2/v1.3; orthogonal to harmonics + Chiron range |
