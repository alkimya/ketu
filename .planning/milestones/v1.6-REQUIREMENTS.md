# Requirements: Ketu v1.6 — Declination Aspects

**Defined:** 2026-06-04
**Core Value:** Cycle calculations must be correct, tested, and performant. If the math is wrong, nothing downstream matters.

## Milestone Scope (LIGHT)

v1.6 adds **declination aspects** — parallels and contra-parallels on the equatorial declination (δ) axis — as a new aspect type, reusing the `body_decl` data already shipped in `CHART_DTYPE` (v1.5). This is the **final lightweight Ketu engine milestone** before the separate Rahu UI project (which consumes `ketu` from PyPI).

**Discipline:** DECLA only. Pure-NumPy, additive (no `CHART_DTYPE` change — a companion function, not a new dtype field). NO declination synastry, NO dedicated CLI surface, NO new bodies, NO applying/separating/timing (in-orb boolean detection only). HARMF-01 (rich `--harmonics` grammar) explicitly deferred.

Research brief: `.planning/research/DECLINATION_ASPECTS.md`.

## v1 Requirements

### DECLA — Declination Aspects

- [ ] **DECLA-01**: User can detect **parallels** between two bodies — same-hemisphere declination within orb: `sign(δ₁) == sign(δ₂) ≠ 0  AND  |δ₁ − δ₂| ≤ orb`. Bodies exactly at δ = 0° (sign 0) form no parallel.
- [ ] **DECLA-02**: User can detect **contra-parallels** between two bodies — opposite-hemisphere mirrored declination within orb: `sign(δ₁) ≠ sign(δ₂)  AND both ≠ 0  AND  |δ₁ + δ₂| ≤ orb`.
- [ ] **DECLA-03**: Declination orb is **derived from per-body orbs**, not a hardcoded constant: `δ_orb(b1,b2) = max((core.bodies['orb'][b1] + core.bodies['orb'][b2]) / 2 × DECLA_COEF, MIN_DECL_ORB)` with `DECLA_COEF = 1/12` (yields exactly 1.0° for Sun/Moon — the published tight consensus) and `MIN_DECL_ORB = 0.5°` (floor so zero-orb bodies Rahu/Ketu/Lilith remain detectable).
- [ ] **DECLA-04**: User can call a **companion detection function** `find_declination_aspects(body_decl)` consuming `CHART_DTYPE["body_decl"]` (shape `(14,)`), returning a `DECLA_ASPECT_DTYPE` structured array (`body1` i4, `body2` i4, `kind` U2 ∈ {"P","CP"}, `gap` f8, `orb` f8); `CHART_DTYPE` itself is UNCHANGED (additive, no dtype ratchet break). Detection is NumPy-vectorizable over a batch of charts (shape `(S, 14)` → `(S, 91)` pair masks) with no Python loop in the hot path.
- [ ] **DECLA-05**: Declination aspects are **documented en + fr** — the parallel/contra-parallel definitions (signed δ, same-hemisphere rule), the body-derived orb formula, the aspect-centric biodynamic framing (parallel ≈ conjunction / contra-parallel ≈ opposition on the δ axis), the explicit parallel ≠ longitude-conjunction distinction, and the symbol/naming conventions (`//` parallel, `#` contra-parallel; text `P` / `CP`). Out-of-bounds interaction noted (mechanically identical; "both OOB" is an interpretive annotation the caller composes).

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Declination (extensions)

- **DECLA-F1**: Applying/separating for declination aspects via `declination_velocity` (`d/dt|δ₁−δ₂| < 0` parallel applying; `d/dt|δ₁+δ₂| < 0` contra applying). Not reported by mainstream sources for declination; in-orb boolean is the complete natal output.
- **DECLA-F2**: Exact-crossing timing (declination-aspect windows) via the `aspect_windows.py` bisection pattern.
- **DECLA-F3**: Declination synastry — parallels/contra-parallels between two charts' bodies.
- **DECLA-F4**: Dedicated CLI surface for declination aspects (e.g. `ketu aspects --declination`).

### Harmonics (carried from v1.5)

- **HARMF-01**: Rich `--harmonics` CLI grammar — multi-harmonic (`h7,h11`) and preset+harmonic mixing (`traditional,h7`). v1.5 shipped only the Tight single-token form.

## Out of Scope

Explicitly excluded for v1.6. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Declination synastry (parallels between two charts) | LIGHT milestone — natal detection only; the companion function operates on one chart's `body_decl`. Deferred (DECLA-F3). |
| Dedicated CLI surface for declination aspects | LIGHT milestone — Python API is the v1.6 surface; CLI deferred (DECLA-F4). |
| Applying/separating + exact-crossing timing for declination | No mainstream source reports it for declination; in-orb boolean is the complete natal output. Deferred (DECLA-F1/F2). |
| Changing `CHART_DTYPE` (new `decla_aspects` field) | Companion function chosen over a dtype field — avoids a ratchet break and the variable-count fixed-dtype trap. `CHART_DTYPE` stays byte-identical. |
| Codeclination (Boehrer mirror across ε) | Separate interpretive technique, not a detection aspect. |
| New rows in the frozen `core.aspects` table | Declination aspects are a SEPARATE structure (`DECLA_ASPECT_DTYPE`); the 14-row `core.aspects` table + its V1/V13 sha256 fingerprints stay byte-identical. |
| New bodies (centaurs, asteroids, fixed stars) | Ketu is considered ~complete; no body additions planned. |
| HARMF-01 (rich `--harmonics` grammar) | DECLA-only milestone; deferred as a v2 candidate. |
| Rust rewrite / PyO3 port | Rejected — NumPy latency is invisible at UI scale; would discard 1627 tests + oracles. Surgical PyO3 only if a real hot path emerges, never a full rewrite. |
