## Overview

Ketu v1.1 evolves the library from a pure astronomical engine into an astronomical-astrological framework. Building on the stable v1.0 foundation (250 tests, 91% coverage, PyPI-published), this milestone delivered three orthogonal capabilities: a verified Lilith calculation, configurable aspect sets (5 majors by default with opt-in harmonics), and an extensible houses module starting with Placidus, Koch, and Porphyry. Five phases (8 through 12) shipped the work, with phases 8/9/10 fully parallelizable, phase 11 integrating CLI on top of phases 9+10, and phase 12 closing with a v1.1.0 PyPI release.

## Cross-Cutting Constraints

These applied to every phase (not just one) and originated from research/SUMMARY.md:

- `core.aspects` array remained length 14 and append-only (Kala uses positional indexing)
- No new runtime dependencies — pure NumPy contract preserved (`pysweph` is test-only, AGPL-safe)
- All new code passes mypy strict, numpydoc-style docstrings
- All new calculations vectorized over date arrays (no Python loops in hot paths)
- DateTime inputs always UTC
- Cache keys include configuration hashes (aspect set, house system) — no stale results after config change
- Coverage gate: ≥90% project, ≥85% per module, ≥95% on new modules (houses achieved 96.75%)

## Milestone Summary

**Decimal Phases:** None inserted in v1.1 (all phases were planned).

**Key Decisions:**

- **CLASSICAL as default aspect set** — Rationale: Pro/classical default; ML harmonics opt-in via `--harmonics`. Kala must explicitly request EXTENDED. Outcome: ✓ Good.
- **Houses module starts with Placidus + Koch + Porphyry** — Rationale: Three systems prove extensibility; others can plug in via the registry. Outcome: ✓ Good (Porphyry doubles as polar fallback).
- **Verify Lilith before fixing** — Rationale: Confirm bug exists and quantify error before changing formula. Outcome: ✓ Good — empirical max |delta| = 179.94° revealed Ketu was computing perigee, not apogee.
- **Vectorize everything new** — Rationale: Houses + aspect filtering must be batchable over date arrays. Outcome: ✓ Good — Phase 9 EXTENDED benchmark is FASTER than v1.0 baseline.
- **Plan 11-06 Option A pivot (forward byte-stability instead of v1.0 backward)** — Rationale: Phases 8 + 9 deliberately broke v1.0 byte-identity (Lilith correction + CLASSICAL default); a backward contract was already lost in reality.
