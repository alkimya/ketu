## Overview

Rahu (10), Ketu (11), and Lilith (12) shipped through v1.6 with `orb = 0` in `core.bodies`
(a deliberate Abu Ma'shar / Al-Biruni modelling choice for fictitious points). Because the
aspect-orb formula is `(orbs[body1] + orbs[body2]) / 2 * coef[asp]`, two zero-orb points can
NEVER form an aspect, and Lilith can never aspect the nodes. The Rahu (frontend) project
surfaced this: with `orb = 0` the node/Lilith aspect grid renders empty.

v1.7 gives the three points a **2° orb** so they enter aspect detection, and surgically filters
out the one tautological artefact a non-zero orb creates — the permanent Rahu↔Ketu Opposition
(Ketu = South Node, exact 180° opposite of Rahu by construction). Shipped as `ketu==1.7.0`, a
**MINOR-not-patch** bump because aspect results change for consumers (Kala must treat the upgrade
as deliberate, not a neutral `pip install -U`).

## Milestone Summary

**Key Decisions:**

- **2° (not another value)** for the three fictitious points — enough to enter aspect, conservative against the frozen planet orbs.
- **MINOR bump, not patch (1.6.1)** — aspect results change for consumers, so the upgrade must be deliberate (Kala opts in). Documented in UPGRADING.
- **Surgical filter, not body suppression** — only the simultaneous `(Rahu, Ketu)` + `Opposition` is filtered; Rahu and Ketu stay fully active for every other aspect and pair.
- **Data-driven single source** — the orb lives only in `core.bodies`; every consumer (`get_orb`, `synastry_orb_limit`, cycles, composite, CLI) inherits with no per-consumer edits.

**Issues Resolved:**

- Empty node/Lilith aspect grid in the Rahu UI (root cause: `orb = 0` → points can never aspect).
- Two new Rahu detections (Sun-Rahu Quincunx, Venus-Rahu Trine) surfaced by the orb change — deliberately pinned in the CLI snapshot, not silently absorbed.
- Pre-flight (39-03) caught two stale ORB-04 defects before publish: leftover `orb = 0` docstrings and a broken `concepts.md#orbs` Sphinx xref in `api.md` (EN+FR).

**Technical Debt / Deferred:**

- **HARMF-01** — Rich `--harmonics` CLI grammar (multi-harmonic, preset+harmonic mixing). Carried forward from v1.5.
- **DECLA-F1** — Declination synastry / applying-timing / dedicated CLI surface for declination aspects (v1.6 shipped in-orb detection only).
- Configurable per-call point-orb override — explicitly out of scope for v1.7 (one global value; runtime override is a larger config-surface decision with no current demand).

**Execution Notes:**
