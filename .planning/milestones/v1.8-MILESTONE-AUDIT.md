## Tech Debt (non-blocking, carried forward)

All four items are from the Phase 40 code review (WR-01..WR-04). None blocks the
milestone goal; none is a regression introduced by v1.8. WR-03 and WR-04 are
pre-existing defects that predate this milestone.

**Phase 40 — declination-speed-field-chart-api**
- **WR-01** (Warning): `0.01` d FD step is a magic number at 3 independent sites
  in `ketu/charts/api.py` (402, 411). Future edit risk: tuning one site diverges
  the others and breaks the exact-match test far from the edit. No functional
  issue today.
- **WR-02** (Warning): `is_ascending_declination_chart` silently classifies NaN
  as neutral (0) — no guard against non-finite inputs (`api.py:615-619`).
  `compute_chart` guarantees finite output; risk is only with hand-built charts.
- **WR-03** (Warning, pre-existing): composite inline aspect loop omits Rahu↔Ketu
  tautological-opposition suppression (`composite/api.py:383-412`). Predates v1.7;
  out of scope for DSPD requirements; no regression introduced by this phase.
- **WR-04** (Info, pre-existing): stale "13-body axis" / "(13,)" docstrings
  (`core.py:22`, `synastry/core.py:24`) — should be 14 since v1.3 Chiron.
  Documentation-only, no correctness impact.

Recommendation: track as backlog. None warrants blocking the v1.8 archive. A future
cleanup phase could fold WR-01 (hoist the 0.01 d step to a named module constant),
WR-04 (sweep the stale 13-body docstrings), and WR-03 (pre-existing composite
aspect-loop suppression) together.
