# Milestone v1.4: Dynamic Harmonics & Chiron Range

**Status:** ✅ SHIPPED 2026-06-03
**Phases:** 28-32
**Total Plans:** 15

## Overview

Make aspect harmonics open-ended — any integer harmonic (H17, etc.) usable as a first-class aspect across the whole detection chain via an on-the-fly generator, without disturbing the frozen `core.aspects` table or its preset fingerprints — then widen Chiron's validity range to 1900–2100, correct its orb to 4° (Pluto parity), recentre the documentation on the 180°-division default (H1/H2/H3/H6), and ship `ketu==1.4.0`.

**Axis order (BINDING):** Phases 28 (dynamic harmonics) and 29 (Chiron orb 4°) were fully independent. Phase 30 (Chiron range) followed Phase 29 (avoids double CLI-fixture churn). Phase 31 (documentation) followed all feature phases (28 + 29 + 30). Phase 32 (release) followed Phase 31.

**Cross-cutting constraints (held):**

- Pure-NumPy runtime NON-NEGOTIABLE — dynamic generation is plain NumPy angle arithmetic; Chiron `.npz` regeneration stayed offline pyswisseph-build-only. No scipy, no new runtime deps.
- Frozen `core.aspects` table and sha256 fingerprints PRESERVED — dynamic path parallel and additive, never mutates the 14-row table.
- `_VALID_HARMONICS` does NOT gate the dynamic path.
- All new calculations vectorizable over date arrays; no Python loops in hot paths.
- 100% coverage + numpydoc BLOCKING.
- Release: pushed `origin/main` AND the tag (RTD follows main, PyPI follows tag).

## Phases

### Phase 28: Dynamic Harmonic Generator + Detection Integration

**Goal**: A user can generate first-class aspects for any integer harmonic `h` on the fly and have them detected through the full aspect chain — `calculate_aspects`, vectorized, batch, cycles, synastry — without touching the frozen `core.aspects` table or its preset sha256 fingerprints.
**Depends on**: Nothing (first v1.4 phase; fully additive)
**Requirements**: ASP-04, ASP-05, ASP-06, ASP-07, ASP-08, ASP-09
**Plans**: 3 plans (2 waves) — ✅ COMPLETE 2026-06-03 (verifier PASSED 5/5)

Plans:

- [x] 28-01: Dynamic harmonic generator — `generate_harmonic_aspects(h)` + `_fold_to_0_180` + `HARMONIC_DTYPE`/`DynamicAspectSpec`, exports, frozen-table guard tests (ASP-04, ASP-05, ASP-08)
- [x] 28-02: `calculator.py` wiring — `dynamic_specs` in `calculate_aspects` scalar/vectorized/batch (`i_asp=-2`) + the two IndexError guards (`find_aspect_timing`, `find_aspects_between_dates`) (ASP-06, ASP-09)
- [x] 28-03: Cross-surface consumers — `dynamic_specs` in `calculate_synastry` (`aspect_type=-2`) and `generate_cycle_series`/`multi` (extended candidate set) (ASP-07)

**Details:**
Angles use the unified 360° convention — `fold_to_0_180(k·360/h)` for `k=1..h//2`, coefficient `k/h`, mirror pairs deduplicated, 0°/360° never emitted, unnamed high harmonics carry a blank symbol. Dynamic rows carry `i_asp = -2` (scalar/vectorized/batch) and `aspect_type = -2` (synastry) sentinels and are indistinguishable in dtype from static-table detections. Per-pair orbs derived from `core.bodies['orb']` × dynamic coefficient. The `core.aspects` sha256 fingerprints (V1 `c5bd177…`, V13 `3258530…`) unchanged; `_VALID_HARMONICS` never consulted on the dynamic path. `ketu/aspects/harmonics.py` is a new module independent of `presets`, 100% covered (96-test suite).

## Milestone Summary

**Decimal Phases:** None in v1.4.

**Key Decisions:**

- Dynamic path PARALLEL to the frozen table, not a replacement (Rationale: fingerprint contract must hold; the dynamic path never grows the 14-row table) — ✓ Good
- Accept ~2× smaller full-circle dynamic orbs; no convention unification (Rationale: user accepted the trade-off; half-circle and full-circle conventions coexist as independent paths) — ✓ Good
- Chiron orb single source `core.bodies['orb']` (Rationale: one edit propagates to synastry/cycles/composite/CLI; no manual duplication) — ✓ Good
- Blocking spike BEFORE committing the 1900–2100 `.npz` (Rationale: validate accuracy on the early perihelion-adjacent wings before locking the embedded data) — ✓ Good (degree=10 held, 8.2× margin)
- v1.4 = additive minor, not a patch (Rationale: dynamic harmonics + Chiron range made the originally-scoped "v1.3.1 docs patch" a minor) — ✓ Good

**Issues Resolved:**

- `find_aspect_timing` / `find_aspects_between_dates` hardcoded table-index lookups guarded against `IndexError` for off-table dynamic angles (synthetic name).
- mypy `--strict` `no-any-return` in `synastry/api.py` fixed via `cast(np.ndarray, ...)`.
- CHANGELOG authored fresh (no stale `Unreleased`); docs `changelog.md` date-stamped (no XX placeholders).

**Issues Deferred (v1.5+):**

- CLI `--harmonics h7` arbitrary-harmonic flag (ASP-F1) — return-type + CLI byte-stability work.
- Formalize the synthetic off-table naming scheme (`H7k1`) as a documented API contract (ASP-F2).
- `find_aspect_timing` orb-derivation design debt (ASP-F3).
- Chiron range beyond 1900–2100 — no demand.

**Technical Debt Incurred:**

None of significance — all 5 phases verified PASSED at their success criteria (28: 5/5, 29: 6/6, 30: 3/3, 31: 4/4, 32: 3/3). Deferred items tracked as ASP-F1..F3.
